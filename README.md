# Mood-Visualizer

このプロジェクトは Author である [@mpyw](https://github.com/mpyw) の気分を継続的に記録し，可視化するプロジェクトです。

| 役割   | 仕組み                                                       |
| :----- | :----------------------------------------------------------- |
| 保存   | データは全てリポジトリ上に JSONL でコミットされます。        |
| 記録   | GitHub Actions の Workflow Dispatch で記録します。           |
| 可視化 | GitHub Pages 上の React アプリで閲覧します。RSS もあります。 |

## 記録形式

`public/data/history-list.jsonl` には，記録がある年月が JSONL 形式で並びます。その月の最初の記録を追加したときにだけ更新されます。

```json lines
{"date":"2025-01"}
{"date":"2025-02"}
{"date":"2025-03"}
```

各年月の記録は `public/data/history/[YYYY-MM].jsonl` に追記されます。

```json lines
{"date":"2025-01-01T00:00:00+09:00","score":5}
{"date":"2025-01-01T12:00:00+09:00","score":6,"note":"楽しいことがあった！"}
{"date":"2025-01-02T09:00:00+09:00","score":4,"note":"今日はロースタート"}
```

| フィールド | Required | 説明                                          |
| :--------- | :------: | :-------------------------------------------- |
| `date`     |    ✓     | 記録日時。ISO 8601 形式でタイムゾーンを含む。 |
| `score`    |    ✓     | 気分のスコア。0 から 10 の整数。              |
| `note`     |          | 任意のメモ。自由なコメント。                  |

> [!NOTE]
> 日付と月の区切りは，閲覧者のタイムゾーンに関係なく常に JST です。
> 記録ファイルの年月も JST で決まります。

コミットメッセージは以下の形式に従います。

```text
YYYY-MM-DDTHH:MM:SS+09:00 / Score [スコア]

[ノート]
```

## 記録のつけ方

[Record and Deploy](https://github.com/mpyw/mood-visualizer/actions/workflows/record-and-deploy.yml) ワークフローを手動実行します。

| 入力              | 説明                                                         |
| :---------------- | :----------------------------------------------------------- |
| `score`           | 0 から 10 のスコア。                                         |
| `note`            | 任意のメモ。                                                 |
| `date`            | 記録日時。空なら実行時刻（JST）になります。                  |
| `notify_slack`    | Slack に投稿するか。                                         |
| `reply_broadcast` | 同じ日の 2 回目以降の投稿を，スレッド外にも表示するか。      |
| `verify_nda`      | NDA に抵触しないことの確認。チェックしないと記録されません。 |

> [!WARNING]
> 次の `date` は入力ミスとして拒否され，ワークフローが失敗します。
>
> | 拒否される入力     | 例                          |
> | :----------------- | :-------------------------- |
> | タイムゾーンがない | `2026-10-19T09:00:00`       |
> | 未来の日時         | 翌日の日付                  |
> | 1 年以上前の日時   | `2016-10-19T09:00:00+09:00` |

Slack への投稿は，その日の最初の記録ならグラフ画像つきで新しいスレッドを作ります。2 回目以降はそのスレッドに返信します。投稿に失敗しても記録自体は保存されます。

## 閲覧形式

| 機能                   | 動作                                                                                                  |
| :--------------------- | :---------------------------------------------------------------------------------------------------- |
| グラフ                 | 1 日 1 点で平均スコアを描きます。1 日の中でスコアが変動した場合は，最低から最高までの範囲を描きます。 |
| 月の選択               | 初期表示は今月です。プルダウンで過去の月を選べます。                                                  |
| 前後月も含めて30件表示 | 記録のある日が 30 日に満たないとき，前月と翌月の日で補います。下の表を参照してください。              |
| タイムライン           | 記録を新しい順に並べます。「Note 付きのみ」でメモつきの記録に絞れます。                               |
| グラフの点をクリック   | その日の最新の記録までタイムラインをスクロールします。                                                |
| PNG で保存             | グラフを PNG 画像として保存します。                                                                   |
| RSS                    | 最新 50 件を `feed.xml` で配信します。独自タグは [`ns.html`](public/ns.html) で説明しています。       |

「前後月も含めて30件表示」は次のように日を選びます。

| 規則                   | 内容                                                       |
| :--------------------- | :--------------------------------------------------------- |
| 選択月の日             | 30 日を超えても全て表示します。                            |
| 補う順番               | 前月の最も新しい日，翌月の最も古い日，と交互に足します。   |
| 片方がない場合         | 残った側だけで 30 日まで補います。                         |
| 横軸                   | 選択月全体（今月なら今日まで）と，補った日を全て含みます。 |
| 選択月以外の日のラベル | `7/1(Wed)` のように月を付けます。                          |

URL のハッシュで特定の月や記録を開けます。

| ハッシュ                            | 動作                                               |
| :---------------------------------- | :------------------------------------------------- |
| `#2026-06`                          | その月を開きます。                                 |
| `#2026-06-15`                       | その月を開き，その日の最新の記録に移動します。     |
| `#2026-06-15T08:04:03.638603+09:00` | その記録に移動します。RSS のリンクはこの形式です。 |

> [!TIP]
> 移動先の記録にメモがない場合は，「Note 付きのみ」が自動で外れます。

## 開発

| コマンド                | 内容                                                     |
| :---------------------- | :------------------------------------------------------- |
| `npm run dev`           | 開発サーバーを起動します。                               |
| `npm test`              | Vitest でテストします。                                  |
| `npm run test:coverage` | カバレッジつきでテストします。閾値を下回ると失敗します。 |
| `npm run lint`          | 型チェック，oxlint，Prettier を実行します。              |
| `npm run fix`           | oxlint と Prettier の自動修正を適用します。              |
| `npm run build`         | `dist/` にビルドし，RSS を生成します。                   |
| `uv run pytest`         | ワークフロー用の Python スクリプトをテストします。       |
| `uv run ruff check`     | Python スクリプトを lint します。                        |

| ディレクトリ      | 内容                                                              |
| :---------------- | :---------------------------------------------------------------- |
| `src/domain/`     | 日付・スコア・集計などの純粋関数。アプリと RSS 生成で共有します。 |
| `src/api/`        | JSONL の取得。                                                    |
| `src/hooks/`      | データ取得の React フック。                                       |
| `src/components/` | 画面の部品。                                                      |
| `scripts/`        | ビルドとワークフローで使うスクリプト。                            |

> [!NOTE]
> テストは `America/Los_Angeles` のタイムゾーンで実行されます。
> 閲覧者のタイムゾーンに関係なく JST で日付が区切られることを確かめるためです。

Pull Request と `main` への push では，[CI](.github/workflows/ci.yml) が上記の lint とテストに加えて actionlint を実行します。
